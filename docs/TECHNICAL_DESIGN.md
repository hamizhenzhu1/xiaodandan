# 个人网址导航站技术方案

## 1. 方案概述

本项目采用纯前端单页应用方案，实现网址的添加、编辑、删除、搜索、分类、排序、导入导出和主题切换。首版不建设后端服务，业务数据保存在浏览器本地，可部署到任意静态网站托管平台。

技术方案重点关注以下目标：

- 保持项目轻量，降低开发和部署成本。
- 使用 TypeScript 和数据校验减少运行时错误。
- 将界面、业务逻辑和存储逻辑分层，方便后续接入云端同步。
- 为核心逻辑和主要用户流程建立自动化测试。
- 保证桌面端、移动端和键盘操作的基本可用性。

## 2. 技术栈

| 领域 | 技术 | 用途 |
| --- | --- | --- |
| 运行环境 | Node.js 22+ | 本地开发、构建和测试 |
| 包管理 | npm | 管理项目依赖和运行脚本 |
| 前端框架 | React + TypeScript | 构建组件和交互逻辑 |
| 构建工具 | Vite | 开发服务器、打包和静态资源处理 |
| 样式 | Tailwind CSS | 响应式布局、主题和界面样式 |
| 数据校验 | Zod | 表单、网址和导入文件校验 |
| 拖拽排序 | dnd-kit | 卡片的鼠标、触摸和键盘排序 |
| 图标 | Lucide React | 提供统一的操作图标 |
| 单元及组件测试 | Vitest + Testing Library | 验证业务逻辑和组件行为 |
| 端到端测试 | Playwright | 验证主要用户操作流程 |
| 代码质量 | ESLint + Prettier | 静态检查和代码格式化 |

首版不使用 Next.js、Redux、后端服务或数据库，避免引入当前需求不需要的复杂度。

## 3. 总体架构

项目按照展示层、业务层和数据层进行划分：

```text
React 页面与组件
        ↓
状态管理与业务服务
        ↓
数据校验与序列化
        ↓
localStorage
```

- 展示层负责页面布局、表单、弹窗、网址卡片和用户反馈。
- 业务层负责增删改查、搜索、分类、排序和主题切换。
- 数据层负责本地数据读取、保存、迁移、导入和导出。
- 所有外部输入在进入业务状态前都必须经过 Zod 校验。

## 4. 推荐目录结构

```text
src/
├─ components/        # 通用组件、网址卡片、弹窗和表单
├─ features/

│  ├─ categories/     # 分类管理

│  └─ theme/          # 主题设置
├─ hooks/             # 可复用 React Hooks
├─ schemas/           # Zod 数据结构与校验规则
├─ services/          # 本地存储及文件处理
├─ types/             # TypeScript 类型
├─ utils/             # 网址规范化等纯函数
├─ App.tsx
└─ main.tsx
tests/                # 单元及组件测试
e2e/                  # Playwright 端到端测试
docs/                 # 产品与技术文档
```

## 5. 核心数据模型

```ts
type Bookmark = {
  id: string;
  name: string;
  url: string;
  categoryId: string;
  note?: string;
  order: number;
  createdAt: string;
  updatedAt: string;
};

type Category = {
  id: string;
  name: string;
  order: number;
};

type AppData = {
  version: number;
  bookmarks: Bookmark[];
  categories: Category[];
  settings: {
    theme: "light" | "dark" | "system";
  };
};
```

所有记录使用 `crypto.randomUUID()` 生成 ID。时间字段使用 ISO 8601 字符串，`version` 用于未来的数据结构迁移。

## 6. 状态与存储方案

### 状态管理

首版使用 React Hooks、Context 和 `useReducer` 管理全局状态，不额外引入 Redux。搜索关键词、弹窗开关等临时状态保留在对应组件内部。

### 本地持久化

- 使用 `localStorage` 保存完整的 `AppData`。
- 应用启动时读取数据并进行结构校验。
- 数据修改后统一通过存储服务写入，避免组件直接操作 `localStorage`。
- 数据无效或版本不兼容时不直接覆盖原数据，并向用户显示可理解的错误信息。
- 存储服务保留统一接口，后续可替换为云端 API 或其他存储方式。

## 7. 核心功能实现

### 网址管理

- 添加和编辑共用同一个表单组件。
- 自动去除首尾空格，并在缺少协议时补全 `https://`。
- 仅允许 `http:` 和 `https:` 协议，禁止 `javascript:` 等危险协议。
- 删除前使用确认弹窗，确认后再更新状态和本地存储。
- 打开外部网址时使用新标签页，并设置 `noopener,noreferrer`。

### 搜索与分类

- 搜索范围包括名称、网址和备注，默认忽略大小写。
- 分类筛选和搜索条件可以同时生效。
- 搜索和筛选结果由当前状态即时计算，不额外写入本地存储。

### 拖拽排序

- 使用 dnd-kit 的 sortable 能力更新卡片顺序。
- 同时配置 Pointer、Touch 和 Keyboard Sensor。
- 拖拽结束后重新计算 `order` 并持久化。
- 为不能或不便拖拽的用户保留键盘排序能力。

### 导入与导出

- 导出时生成包含版本号的 UTF-8 JSON 文件。
- 导入时限制文件类型和合理大小，并完整校验数据结构。
- 导入前展示数据摘要，并要求用户确认是否覆盖现有数据。
- 校验失败时不修改当前数据，并给出具体错误提示。

### 主题

- 支持浅色、深色和跟随系统三种模式。
- 使用 CSS 类和 `prefers-color-scheme` 控制主题。
- 用户选择写入本地设置，避免刷新后丢失。

## 8. 可用性与安全要求

- 所有可点击操作使用语义化按钮或链接，并提供明确的焦点样式。
- 弹窗需要支持焦点管理、Esc 关闭和键盘操作。
- 图标按钮必须包含可访问名称，状态变化应提供文字反馈。
- 移动端触控目标保持足够大小，页面在常见屏幕宽度下不得横向溢出。
- 用户输入以普通文本渲染，不使用未经处理的 HTML。
- 外部链接只允许 HTTP(S) 协议，并使用安全的新窗口参数。
- 从第三方获取网站图标失败时显示本地占位图标，不影响网址打开。

## 9. 测试与验证方案

### 单元测试

重点覆盖：

- 网址补全及协议白名单校验。
- 网址的添加、编辑、删除和排序逻辑。
- 搜索和分类筛选逻辑。
- 本地数据读取、写入、异常及版本处理。
- JSON 导入校验和导出内容生成。

### 组件测试

重点覆盖表单校验、确认弹窗、网址卡片操作、空状态和主题切换。

### 端到端测试

使用 Playwright 验证以下主要流程：

1. 添加网址并在刷新后恢复。
2. 编辑和删除已有网址。
3. 搜索、分类筛选和拖拽排序。
4. 导出数据后重新导入。
5. 切换主题并在刷新后保持。
6. 在桌面和移动端视口完成核心操作。

每次交付前至少运行类型检查、代码检查、单元测试、生产构建和核心端到端测试。

## 10. 构建与部署

项目构建后生成静态资源，可部署到 Cloudflare Pages、Vercel、Netlify 或 GitHub Pages。首版推荐使用 Cloudflare Pages 或 Vercel，通过 Git 仓库自动构建部署。

建议提供以下 npm 脚本：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "test": "vitest run",
    "test:e2e": "playwright test",
    "lint": "eslint .",
    "format:check": "prettier --check ."
  }
}
```

## 11. 后续扩展

若后续增加账号和多设备同步，可在保持组件与业务接口基本不变的情况下增加 API 层，将本地存储服务替换为远程数据仓库，并根据需求引入身份认证、服务端接口和关系型数据库。

在进入云端阶段前，需要单独设计数据同步冲突、权限、隐私、迁移和备份策略，不在首版范围内。
